# 故障排查

## 电池一直显示“—”

先打开悬停详情或 Windows 完整详情查看原因，再按以下顺序检查：

1. 本机 Codex 是否能正常打开并处于登录状态。
2. 设置的路径是否指向 Codex 本体，而非 Codex Battery。
3. 相同 Codex 可执行文件是否识别当前用户的 ChatGPT 登录。Mac GUI 与终端 PATH / 环境可能不同。
4. 当前网络是否允许 Codex 查询额度；代理行为由 Codex 自己的配置决定。
5. 当前登录是否仅为 API Key，或账号服务没有返回有效额度窗口。

失败与缺失保持未知，不能根据重置时间已到来认定额度恢复。

## 打开新版却还是旧界面

Windows 单实例机制会唤起已有进程。从托盘选择“退出管家”，再运行新 EXE。关闭详情窗口的 X 只会收回托盘。

macOS 从菜单栏退出后，再打开新 `.app`；重复启动与唤醒行为仍需在 Mac 真机验证。

## 看不到浮窗

Windows：从托盘右键显示小浮窗，或打开详情窗口选择“小浮窗模式”。

macOS：在菜单栏右键选择“显示 / 隐藏电池”。设置中也有开关。

位置完全离开所有屏幕时，程序启动会回到可见区域。部分跨屏、缩放与全屏场景尚需实测。

## 重置卡显示待更新

服务端未返回有效 `availableCount`，或这次账号数据不可用。不要根据消息条数、卡详情列表长度或他人账号的数值手动补成 0 或 2。

## 没有 Tibo 消息

程序只显示最近 3 天的重置卡相关帖子。没有符合条件的帖子时隐藏消息区。第三方公开源可能过旧或不可用，打开消息状态或作者 X 主页核实；抓取成功不代表监控完整。

在设置中确认消息功能已开启。自定义 RSS 必须是 HTTPS，且 channel 身份和原帖链接属于 `@thsottiaux`。

## macOS 无法构建

先运行 `swift --version` 和 `xcode-select -p`。需要 Swift 5.9+、Apple macOS SDK，并在 Mac 上构建。Windows 的 Swift 编译器不能替代 AppKit SDK。

macOS 当前是待验证实验版。保留首个编译错误、系统/架构和 Swift 版本，用于修复；不要把只通过文本检查当作构建成功。

## 系统提示未知发行者或无法验证开发者

Windows 程序未做发行者签名，Mac 脚本只做 ad-hoc 本地签名。公开分发前需由维护者准备相应签名与 Mac 公证，不要求用户关闭 Windows Defender、Gatekeeper 或系统完整性保护。
