# 版本与产物约定

## 当前版本

Windows 首个对外整理版定义为 **1.0.0**。目前功能已形成可使用的本地工具，并经过本机检查与真实账号验证，适合从1.0.0建立正式发布记录。此前临时编号属于开发过程，不沿用为正式历史。

macOS 仍为 **0.1.0 实验版**，尚未在Mac编译和真机验证，继续单独标注。

## 以后如何增加版本

| 变化 | 示例 |
| --- | --- |
| 修复问题，原有使用方式兼容 | 1.0.0 → 1.0.1 |
| 增加功能，原有使用方式兼容 | 1.0.1 → 1.1.0 |
| 不兼容的大改动或配置迁移 | 1.1.0 → 2.0.0 |

日常重新构建、改写说明、内部验证不自动增加版本。准备发布实际更新时才修改版本并写入CHANGELOG。发布过的版本不重写含义。

## 单一版本来源

根目录 `VERSION` 为Windows发布版本。构建时生成 `windows/obj/VersionInfo.cs`，为EXE写入程序集版本、文件版本和产品版本；主窗口、请求标识与ZIP文件名读取同一版本。

不要手动修改生成的版本源文件。更新版本后还应同步README、使用说明和CHANGELOG等对外文档。macOS实验版版本暂由 `macos/Info.plist` 等原有文件维护。

## 本机只保留最新版

- 程序固定输出到 `windows/dist/`。
- 便携包输出到 `artifacts/CodexBattery-windows-版本号.zip`，新包成功创建后清理旧Windows包。
- 不创建 `dist-v*` 目录；不在项目目录堆积历史发行包。
- 如需对外留存历史，使用Git标签和Releases或内部制品库。
- 覆盖正在运行的EXE前先退出管家，更新完成后从固定路径启动。

版本变化不改变现有 `%LOCALAPPDATA%\CodexQuotaManager` 配置目录。
